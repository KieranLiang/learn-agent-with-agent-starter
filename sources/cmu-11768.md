## L01 什么是 agent 🟢

- 定义沿用 Russell & Norvig：通过传感器感知环境、通过执行器作用于环境。对应到 LLM agent：环境（仓库、网站）、观察（消息、文件、工具结果）、动作（回复、改文件、跑命令）、奖励（测试通过、评审打分）。
- 两句核心话：**“动作也是 token”**（工具调用只是模型能预测的另一种 token 序列，harness 负责解析、校验、执行，再把结果作为观察塞回去）；**“agent 就是放在循环里的模型”**。
- 六种能力：准确调用工具、长上下文连贯、可定制、复杂任务管理、理解环境、安全。每种能力都有两条实现路线：**训练模型** 或 **做 harness 工程**。这张六行两列的表可以当整门课的地图。
- “agent 是系统，不只是模型”：模型 + harness + 沙箱 + 推理服务 + 监控 + 训练。
- 标本：开场互动题——把 6 个任务（排查结账故障、给 5 万客户发邮件、报税、迁移支付 API、抢演唱会票、调胰岛素剂量）分到“自主做 / 先问 / 绝不”三栏。很适合当 单元 1 的第一道“判”。
- 标本：mini-swe-agent 的最小循环，约 20 行 Python。

## L02 工具使用 🟢（约束解码部分 🔴）

- 工具 = 模型调用外部程序的接口。**“模型提议，外部软件决定是否以及如何执行。”**
- 好处两类：扩展（拿到参数里没有的信息或动作）、代劳（把外部程序做得更可靠的事交出去）。只有收益大于延迟、成本、失败和风险时才调用。
- “造一个 ChatGPT 需要哪些调用”：从想要的能力倒推，每种交互定义一个窄接口。`finish(text)` 是 harness 的控制动作，不是外部程序。
- 代码是“元工具”（CodeAct）：表达力强，但更难约束、影响面更大，要配沙箱、资源限制、权限和审计。
- 机制：messages 经 chat template 序列化成一条 token 序列；工具 schema 进 prompt；模型吐出调用；用 call ID 把结果对回调用。不同模型的调用格式不一样，schema 是同一份。
- 约束解码（JSON Schema + 语法掩码）**只保证形式，不保证事实、权限、选对工具或任务成功**。
- REST 与 MCP：让 agent 直接 curl 会把密钥暴露给它的 shell。MCP 的价值之一是**凭证代理**：服务器收一个凭证、对上游用另一个，模型两个都看不到。
- 并行调用：三个独立调用串行约 6.4 秒，并行约 2.8 秒。只有互不依赖时才能并行。
- 评估四层：选对工具、参数对、顺序对、任务成。外加效率、可靠性、安全三个运营维度。

## L03 长上下文管理 🟢 + 🔴

- **历史线性增长，输入总量二次增长**：每次调用都要重读全部历史（5 次调用累计 80K）。
- 1,500 个 OpenHands 会话的平均构成（均值 77,922 token）：工具结果 37%、系统提示加工具定义 23%、工具调用 20%、用户 9%、推理 9%。**最大头是工具结果。**
- 两个挑战分开看：容量（模型用得上证据吗）和效率（系统付得起吗）。标称窗口不等于有效窗口。
- 缓存：稳定前缀（指令、工具、示例放前面），变化的状态往后追加，别引入无谓变动（时间戳、工具顺序）。缓存命中的输入大约便宜一个数量级。缓存省钱，但不减少模型看到的历史。
- 压缩（compaction）：
  - 保留什么：目标和约束**原样保留**；决策、进度、ID 编码成检查点；最近一段原样保留；大块证据**外置**（2.4 万行日志变成“3 个失败 + 命令 + 文件路径”）；重复和被推翻的尝试丢弃。
  - 四个策略决定：何时触发、选哪段、换成什么、失败怎么恢复。
  - **反复压缩会漂移**：“用 CUDA 12.4”→“12.x”→“较新的 CUDA”→约束消失。
  - 评估压缩看“续写”：埋入约束，压缩后看后续决策对不对。
- 🔴 后置：滑窗注意力、线性注意力、DeltaNet、稀疏注意力、KV 压缩、RoPE、YaRN、分页 KV 缓存。

## L04 记忆与技能 🟢

- 更新 agent 的三个位置：上下文窗口（保真但贵且吵）、外部产物（可检查、可编辑、可移植，但要归纳和维护）、模型权重（快但不透明）。
- 经验三类：片段（完整轨迹）、事实、技能。记忆是“发生过什么”，技能是“怎么做”。
- 技能两条来路：人写（意图清楚，但要专家时间）和 agent 归纳（要评判、验证、筛选）。
- SKILL.md 的**渐进式披露**三层：元数据一直在上下文里；正文触发时才加载；附带文件读到才加载。
- SkillsBench：人写的技能把平均通过率从 33.9% 提到 50.5%；聚焦的技能收益更大；**87 个任务里有 13 个被技能拖累**。
- 实用建议：别从零写技能，在 agent 刚做完一遍想复用的流程后让它生成，再测几次。
- 标本：OpenHands 维护代码审查技能的闭环——记录每次运行、打分、找反复出现的失败、改 SKILL.md。
- 记忆冲突的四种操作：新增、更新、删除、不动。
- 技能用文本还是代码：文本灵活但不省步数，代码可执行、可测试、可组合但脆。
- 技能生命周期：学（评判、归纳、准入）→ 用（检索、行动）→ 养（修复、淘汰）。**检索太多会掉分。**

## L05 规划与任务分解 🟢

- 标本：采购 GPU 工作站的长任务。反应式 agent 把四个独立搜索挤在一个上下文里，四家都不合适却硬选一家并提交了不可撤销的申请。
- 计划的定义：对未来行为的显式表示；只针对这一个任务（技能才跨任务）；是提议，不是保证。
- Plan Mode：只读调查 → 澄清问题 → 写计划 → 人审 → 执行。
- 推理和行动的区别：行动会改变状态、会暴露新信息、会失败、可能不可逆。
- **“难点变了”**：对 LLM 来说写出像样的计划很容易，难的是知道自己对世界的理解对不对。所以现在的设计少做深度搜索，多做观察、验证和出错恢复。
- 光谱：开发者写死的流程 → 先计划后执行 → 边做边改。事先定死更快、更便宜、更可预测；重新规划能适应新信息。
- 加规划结构的四个理由：模块化、反馈、长程、控制。
- 警惕固定角色的多 agent：角色在任务来之前就定死；交接靠摘要，会丢上下文。
- 失败模式：想太多（分析瘫痪、乱动、过早放弃）；一个早期错误推断污染后面所有决策（Vending-Bench）；全局约束跨子任务时容易被违反。
- 计划也是安全边界：ReAct 让每个网页都能影响下一步动作；先写好程序，就只接受网页里的值，不接受新动作。
- 设计清单四问：子任务可分吗；哪些失败该改计划；怎么阻止错误和上下文累积；哪些信息和权限要隔离、谁批准不可逆动作。

## L06 Coding agent 🟢（训练部分 🔴）

- 三要素：prompt、工具、LLM。
- **定位 → 修改 → 验证** 循环。标本：`config.get("retries") or 3` 把合法的 0 变成 3，改成 `is None` 判断（经典的真值判断与 `or` 陷阱）。
- 只给一个 shell 也能做 coding agent（mini-SWE-agent）。
- 编辑格式有四种（整文件、搜索替换、统一 diff、补丁），**格式影响很大**：Aider 的重构测试里从 20% 到 61%。
- SWE-bench 的判定：原来失败的测试变通过，原来通过的保持通过。
- 开发者只有约一成多的时间在写代码（Meyer 2019）。测试通过只是一步，不是发布决定。

## L13 安全 🟢

- 五个真实事故当标本：OpenClaw 未经批准删邮件、PocketOS 删生产库和备份、Copilot 泄露私有文档（CVE-2025-32711）、Cline 供应链投毒、指挥 agent 盗刷支付卡。
- 四种威胁模型：恶意用户、提示注入、agent 犯错、手段不当（目标对但方法不对，比如直接抄答案）。
- 四类防线：红队与安全训练；沙箱（文件与进程、网络、资源三道边界）；凭证（藏起密钥不等于防住滥用，要细粒度、短时效、凭证代理）；监控（规则查精确条件，模型查需要上下文的问题；**检查要在执行之前完成**）。
- 原则：访问规则、检查、日志、停止开关都要放在 agent 够不着的地方。
- 评估指标四个：任务完成率、不必要的拒绝、不安全尝试、造成的实际伤害。
- 基率陷阱：1% 不安全、抓住 90%、误报 1%，结果只有 48% 的告警是真的。

## L14 OpenHands 🟢

- 历史线：补全（到 2023）→ SWE-bench（2023-10）→ Devin（2024-03）→ OpenDevin、SWE-agent → 2026 进入部署阶段。
- 单 agent 基线：少量通用工具（改文件、跑命令、浏览）加技能加 MCP。加 agent 要有明确目的：并行、独立审查、控成本。
- 自动化的形状：触发 → 上下文 → 隔离运行 → 产物 → 检查。Software factory：分诊 → 实现 → 审查 → 合并检查。

## L15 编排与监控 🟢

- 单 agent 与显式流程的取舍。流程的好处：一致、省（某步可以用小模型甚至纯代码）、可测试。代价：不够灵活，信息流要手工管。
- LangGraph 客服例子：节点、条件路由、共享状态、检查点与恢复、人工打断。
- 标本：用 Docent 查 GPT-5.1 Codex 为什么比 GPT-5 Codex 低（40% 对 27%）。结论是超时，去掉超时任务后排名反转。很适合教“分数不解释原因”。
- 标本：Hodoscope 聚类行为，发现 Commit0 里 agent 从 git 历史里捞回被删的代码。

## L18 多 agent 🟢

- 三个动机：更好地利用推理算力（上下文隔离、并行、专门化、多路探索）；任务本身就涉及多方；当训练和评估环境。
- 固定角色（ChatDev）对比开放式委派（按需生成同构的子 agent）。
- 协调方式：管理者出依赖图、结构化消息、用 Git 并行；黑板；公开任务队列加只追加的留言板。
- 泼冷水的数据：Terminal-Bench 上互相交流的两人团队 60.67%，不如各做各的取最好 62.36%。

## L19 人与 agent 的交互 🟢（2026-11-25 补读课件文字）

- 嘉宾 Valerie Chen（Stanford University）（第 1 页）的核心论点是：“在许多 agent 场景下，过程才是关键”（“For many agentic contexts, process is the key”）（第 5 页），模型不再孤立回答单条提问，而是参与协作工作（collaborative work）（第 12 页）。构建协作型语言模型（LM）agent 有三条线：针对 agent 场景优化交互、从 agent 场景的交互中学习、理解使用 agent 的下游影响（第 14、15、89 页；第 41 页将第三点写为针对协作场景训练用户）。
- 人机交互从“前 agent 时代”进入“agent 时代”（第 27 页）：任务前从“调用预定义服务”变为“说清目标与约束”；任务中从“等待预测结果”变为“监控进度、打断与纠偏（interrupt/steer）”；任务后从“接受或推翻预测”变为“检查结果并要求后续跟进”。在数据科学 agent 的“西雅图开咖啡店投资分析”标本中，如果 agent 闷头跑完全程交出“270 words describing the steps and actions and 770 lines of code”，一旦出错用户就得硬着头皮读代码（第 2 页）；改成先给出阶段性统计、主动询问数据采集背景并提供脚手架（scaffolds），才能让用户结合领域知识把关后续分析（第 3–4 页）。（该页表格提到的指南编号 G1–G16 的具体条文，课件没说清。）
- 从被动式 AI（reactive AI：`output = LM(prompt)`）转向主动式 AI（proactive AI：`when to show, what to show = LM(context)`），上下文涵盖用户、历史会话、代码和用户提示（第 28 页）。在软件工程用户心智建模（User Mental Modeling，ToM-SWE）的真实使用中（具体系统设计图文字未在课件提取出，细节课件没说清），它对“带有先前上下文、略微欠指定（somewhat underspecified）的查询”最有用，但面对“非常模糊的查询（very vague queries）”仍会吃力（第 31、34 页）。在一项针对主动干预（proactive interventions）的 5 天实地研究中，研究者在“5,732 intervention points”里收集到“229 interactions”（第 37 页），系统可用性（System Usability）调查在“Quick to Learn”“Easy to Use”“Would use often”“Well Integrated”四项上给出“93%”“87%”“86%”“67%”的同意/强烈同意比例（各百分比与这四项的具体对应关系因排版缺失，课件没说清）（第 38 页）。
- 从隐式交互信号（implicit interaction signals）学习：大多数多轮交互没有显式反馈（explicit feedback）（第 47 页）。PULSE 框架先训练模型 `f` 预测用户评分——从原始轨迹 `X` 中抽取“用户消息总数（Total user messages）”“agent 是否漏测代码（Did the agent fail to test code?）”“agent 是否提交代码（Did the agent commit code?）”“用户情绪（User sentiment）”等语义特征，使相关性比直接喂入 `X` 的基线提升“over 26%”（第 53–54 页）——再用预测驱动推断（Prediction powered inference）结合少量有标注和大量无标注交互比较方案 A 与 B 的效应量（effect size）（第 49–51 页）。在超过“15k users”的线上实验中，更换语言模型（LLM）影响最大（“6-8% difference”），改变推理策略影响较小但显著（“3% difference”），而减少记忆（Reducing memory）“had no significant difference”（第 56–57 页）；PULSE 相比朴素基线（naive baseline）把置信区间（confidence intervals）最多缩小“up to 40%”（第 58 页）。这类隐式信号也用于训练评估器（critic model）和实时强化学习（real-time RL）（第 59–61 页）。
- 下游影响（不能只看自动评测）：研究者设计了三步实验（第 70–74 页）——先用 agent 或聊天机器人建网站通过测试，再用结合抽象语法树（AST）即时生成的个性化理解测验（涵盖记忆 Memory、归属 Authorship、行为目的 Purpose/Behavior 三类题）检验用户是否读懂自己提交的代码，最后剥夺 agent 只留聊天机器人要求扩展三项新需求——结果使用 agent 的用户生产力更高，但即时测验暴露出他们“对代码理解很差（expose poor understanding）”，后续扩展略好也“mostly due to higher initial accuracy”（第 75–78 页）。从表现最好的“top users”总结出三条习惯：“1) Avoid ‘lazy’ prompting strategies — write prompts in technical terms”“2) Actually read your code”“3) Strive for simpler code — less lines, comments”（第 79 页）。此外，冗长代码不仅害人也害 agent 自己：相比人类，agent 编辑往往添加更多代码行（“p=0.04”），且倾向于加入输入校验或错误处理却在后续代码中未能妥善处理（“p=0.01”）（第 80 页）。
- 培训人更好地使用 AI 同样有效：在模拟前线部署工程师（Forward deployed engineers，FDE）角色并用整体评分表（holistic set of rubrics）训练学生时，使用 Claude Code 的学生取得了更大提升，且学习过程是非线性的（第 82–85 页，具体分数变化数值图表未印出，课件没说清）。
- 对我们：可直接用在 **单元 21（放手与把关）**、**单元 12（可靠性与评估）** 和 **单元 4、9（停止审批与协同过程）**。开头的“770 行代码一次性甩出来 vs 边做边核对背景”（第 2–4 页）和“before/during/after”三阶段对比（第 27 页）很适合放进 单元 21 讲“人该盯住哪里”；“生产力上升但理解力下降”、top users 三条习惯和“冗长代码拖累后续 agent”（第 76–80 页）适合当 单元 21 的反面与正面标本；PULSE 用用户情绪、漏测、追问次数等隐式交互信号评估 harness 改动（第 53–58 页），可补进 单元 12。

## L20 轨迹上的搜索 🟡（2026-11-25 补读课件文字）

- 从同一个起点和全新环境并行采样多条独立轨迹称为重复采样（Repeated sampling / Parallel attempts），采样分布受温度 `T` 控制：`PT (xt | x<t) = softmax(zt /T )`，随机性既影响推理也影响工具动作，但推理模型（reasoning models）可能会把温度固定在 `1.0`（第 2–4 页）。
- 覆盖率（Coverage）与 `pass@k`（`k` 次尝试至少成功 1 次的概率）：若单次成功概率为 `p`，则 `P(at least one succeeds) = 1 - (1 - p)^k`（第 5 页）。`pass@k` 对应“拥有能完美区分对错候选的神谕（oracle）”时的上限成功率；图中 `p = 25.0%`（`At k = 1: 25.0%`）随 `k` 增大趋近 `100%`（第 6 页）。提高覆盖率的手段包括增大采样数、调高温度（不太适用于推理模型）、单次生成多回复（不太适用于 agent）、使用多样提示词（diverse set of prompts），以及在训练中激励多样性或直接优化 `pass@k`（第 7 页）。
- 采出正确答案不等于选得出正确答案（第 8 页）。选择答案依赖两类验证信号（Verification signals）：真实基准检查（Ground-truth checks，如数学证明检查器、代码参考测试）与预测正确性（Predicted correctness，如预测测试、reward model 如 LLM-as-a-judge、候选间相似度）（第 10 页）。常见选择方法有 Best-of-N（如 SWE-Gym 用测试给完整 OpenHands 轨迹标 YES/NO 来微调结果验证器，按最高分返回，第 11–12 页）、自洽性（Self-consistency，用多数投票近似最小贝叶斯风险 Minimum Bayes risk，第 13 页）以及按代码执行输出聚类投票（Consensus over execution results，第 14 页）。但验证器不完美会卡死上限：第 15 页曲线表明，当 `p = 25.0%`、接受正确答案概率 `q = 95%`、误接受错误答案概率 `r = 10%` 时，即使 `k` 不断增大，验证器选出的成功率也只收敛到 `Limit as k grows: 76.0%`（第 15 页）。
- 迭代精炼（Iterative refinement）利用反馈顺序修改候选解，但可以并行精炼多个候选（第 17 页）。Reflexion 的循环是“尝试 → 评估器计算/预测奖励 → 生成反思反馈 → 重试同一任务”（第 18 页），反馈来源同样对应那四类验证信号（第 19 页）。然而没有 oracle 标签时，自我修正的局限在于“一些错答案会变对，一些对答案也会变错”，自我批判可能保留原本的盲区（“Self-critique can preserve the original blind spot”，第 20 页）。Parallel-Distill-Refine（PDR）结合广度探索与精炼：把多个候选压缩成一份摘要（“distill”），让下一轮尝试在共享的有界工作区里条件依赖于这份摘要（第 21 页）。
- 面向长轨迹 agent 的汇总与筛选：先用 LLM 为每条轨迹生成结构化摘要（包含 `key_discoveries` 和 `solution_approach`）（第 23 页），再用递归锦标赛投票（Recursive Tournament Voting，RTV）让 LLM-as-a-judge 在小组里比对摘要，聚合多次有噪声的判定并将胜出者逐轮晋级（第 24 页）。在 100 个 SWE-bench 任务上，结合多个摘要与 RTV 筛选在消融实验中进一步提升了表现（第 25 页，具体柱状图数字课件没说清）。
- Harness 搜索与算力预算分配法则：Meta-Harness 固定模型权重，把历次 harness 代码、得分和运行轨迹（traces）存进文件系统，让提议 agent（proposer agent）读记录后直接编辑 harness 再评测（第 27–28 页）；WHALE 则交替联合优化模型权重与搜索 harness（第 29 页）。最后一页给出诊断口诀：如果 `pass@k` 本身低，就把算力花在增加采样广度或反馈精炼上；如果最终准确率远低于 `pass@k`，就把算力花在改进选择器上（第 30 页）。
- 对我们：非常适合拆进 **单元 12（可靠性与评估）** 和 **单元 14（成本）**，以及 **单元 10（推理时的搜索与验证）**。`pass@k` 与“不完美验证器的上限（`p=25%`、`q=95%`、`r=10%` 时极限仅 `76.0%`）”能直观教清为什么验证器决定系统天花板（单元 12）；“Self-critique 可能保留盲区”（第 20 页）与第 30 页的“pass@k 低加广度，最终分远低于 pass@k 改选择器”直接能当单元 10、12 的题；训练期优化 `pass@k` 和 WHALE 联合训练（第 7、29 页）则按总表归为后置。

## L21 搜索与规划 🟡 + 🔴（2026-11-25 补读课件文字）

- 嘉宾 JY Koh（第 1 页）承接上一讲的“完整轨迹采样与重排”，进入结构化搜索（Structured search）：在部分解（partial solutions）上维护前沿（frontier）、决定扩展哪一枝、用环境结果或世界模型（World Models）评估动作后果，并拆解依赖子任务（第 2–3 页）。
- 传统树搜索（DFS 的栈 LIFO、BFS 的队列 FIFO、蒙特卡洛树搜索 MCTS、专家迭代 Expert Iteration、AlphaGo Zero，第 6–14 页）之所以难直接搬到语言模型上，课件用一张四行对照表点破原因（第 15 页）：棋类游戏的“状态”是紧凑棋盘，“转移”是精确便宜的模拟器，“动作”可枚举，“结果”毫不含糊；而语言模型面对的是“历史与隐藏信息”“工具、副作用或预测”“生成的文本与工具参数”以及“模糊的任务成败”（第 15 页）。第 77 页补了一句关键差异：落子位置可复用，新生成的想法却常直接分叉出新分支，且“看起来合理不代表有用（Plausible does not mean useful）”。
- 语言空间搜索（Search over Language）：思维树（Tree of Thoughts，ToT）把生成、评估（Heuristic）与遍历控制器（Controller）拆开（第 17–21 页），在 100 道困难 24 点（Game of 24）上把 GPT-4 成功率从 IO 的“4.0%”、CoT 的“7.3%”、CoT-SC（100 samples）的“9.0%”拉到 ToT（breadth 1）的“45%”与 ToT（breadth 5）的“74%”（第 22 页），其评估器是将 `impossible`/`likely`/`sure` 映射为人工权重 `0.001`、`1`、`20`（第 83 页）。思维图（Graph of Thoughts，GoT）允许合并不同分支的内容，在 ChatGPT-3.5 的 128 数排序上把相对 ToT 的中位误差降到“≈38”（减少“about 62%”，成本降“>31%”），在 32 元素集合交集上精确成功率达“43%”（ToT 为“31%”，CoT 为“6%”）（第 23–26、100–101 页）。搜索流（Stream of Search，SoS）则把探索、失败（“No Solution”）和回溯全写成文本，用 250M GPT-Neo 在 50 万条轨迹上从头训练，在 1 万道测试题上把准确率从仅训最优路径（OP）的“25.73%”提高到“51.27%”（高出“25.54 percentage points”），经 STaR/APA 进一步升至“55.59%”和“56.52%”（第 27–32 页）。
- **环境内接地搜索（Environment-grounded search）与回溯代价**（重点实用标本）：在真实环境（如 Lean 证明器或网页，第 34–36 页）里分叉扩展会带来三大问题：改变世界状态（STATE CHANGES）、增加工具与等待延迟（LATENCY）、以及回溯可能无法恢复原状（BACKTRACKING）（第 41 页）。第 42、78 页的结账标本极具教学价值：点“SUBMIT ORDER”后再点“BROWSER BACK”，页面虽然回到结账表单，但服务端状态已经变成“Server: order exists”——“同一页面可以隐藏不同的世界状态（The same page can hide a different world state）”（第 78 页）。用“Reset and replay the action prefix”做 5 步网页搜索时，VisualWebArena（GPT-4o + SoM）成功率从“18.9%”升到“26.4%”，WebArena（GPT-4o）从“15.0%”升到“19.2%”，但重放代价高且不可逆动作仍无法回退（第 39–40 页）。
- **世界模型（World Models）的三条实现路线**（第 44–54 页）：区别于执行后看对错的验证器，世界模型在动手前输入“当前状态 + 提议动作”预测下一状态或奖励（第 44–45 页）。第 54 页把三类选择并排对比：1）自然语言预测后果（如 RAP、WebDreamer，在网购点类目前先想象页面变化再走一步重规划，风险是“看起来合理但错误的未来”，且 WebDreamer 中更长的想象步数会因误差累积反而降低成功率，主实验只用一步前瞻 one-step lookahead，第 46–50、54 页）；2）学习到的执行动力学（如 Code World Model，CWM，用 32B 开源权重模型预测 Python 语句对局部变量或 Docker 命令的状态变化，风险是预测误差与分布偏移，第 51–52、54 页）；3）可执行转移程序（如 WorldCoder、GIF-MCTS，让 LLM 写代码当模拟器，风险是“一条写错的规则会变成跑得飞快的错误模拟器”，第 53–54 页）。
- **任务分解、递归与依赖图调度**：
  - 递归语言模型（RLM）把超长提示当作持久化 REPL 里的外部变量，主模型写代码检索切分后再把片段交给子模型调用（第 57–58 页）。在 6–11M token 的 BrowseComp-Plus 上，直接用 GPT-5 超出窗口，压缩（Compaction）得“70.5%”，仅 REPL 得“88.0%”，RLM 深度 1 得“91.3%”，OpenCode + offload 得“94.0%”；在 32K token 的 OOLONG-Pairs（F1）上，Direct GPT-5 仅“0.1”，仅 REPL 为“43.9”，RLM 深度 1 为“58.0”，深度 3 为“76.0%”（第 59 页）。但并非越深越好：在 CodeQA 上 Qwen3-Coder 仅用 REPL 得“66%”，深度 3 反而降到“44%”（第 60 页）。
  - 递归代理优化（RAO）学习何时异步委派，虽然在 TextCraft-Synth（“73% → 96%”）、Oolong-Real（“0.203 → 0.320”）和 DeepDive（“24% → 40%”）上都提了分（第 63 页），但耗时高度依赖任务结构：在分支独立可并行的 Hard TextCraft-Synth 上把耗时从“180.0”秒压到“73.3”秒，而在后一步依赖前一步发现的 DeepDive 上，单 agent 只需“13.3”秒，RAO 却拖到“233.0”秒（第 64 页）。
  - 依赖图与工作区隔离：MACU 由管理者维护可变任务有向无环图（mutable task DAG），等所需输入就绪再并行派发子任务并随新证据改计划（第 66–69 页）；用 Qwen3.6-27B worker 配 Opus 4.6 manager，Odysseys 成功率从“8.5%”升至“34.0%”（中位耗时从“162.4”分钟降至“110.3”分钟），Online-Mind2Web 从“52.2%”升至“55.6%”（但中位耗时从“18.5”分钟升至“33.6”分钟）（第 70 页，其余基准见第 94 页）。CAID 则让多名工程师各自在独立的 `git worktree` 中修改代码，把“合并提交与跑集成测试”本身当作显式任务（第 71–73、80 页）。第 74 页用阿姆达尔定律（Amdahl's Law）点明：并行加速比受限于关键路径（critical path），协调与集成时间也算在关键路径里。
- 对我们：MCTS、AlphaZero、SoS 轨迹训练和 CWM 属于总表里的后置内容（树搜索与训练），但三块工程思想可直接落进课程：1）“浏览器返回键不等于服务端回滚”（第 42、78 页）和三种世界模型风险表（第 54 页）适合 **单元 4（撤销能回退什么 / 不可逆动作）**；2）RLM 把超长输入放到 REPL 外部按需读取并显著胜过 Compaction（第 57–59 页）能直接补充 **单元 5（上下文工程 / 外置）**；3）RAO 在独立任务省时、在强依赖任务反而慢十多倍（“13.3 → 233.0”秒，第 64 页）、MACU 的任务 DAG 与 CAID 的 `git worktree` 隔离合并（第 70–73 页）以及关键路径限制（第 74 页），非常适合 **单元 9（多 agent 与编排）** 和 **单元 17（后台 agent）**。

## L22 如何信任你的 AI agent 🟢（2026-11-25 补读课件文字）

- 嘉宾 Karthik Narasimhan（Princeton University）（第 1 页）开场用两个极端切入——要么“Review every line”（逐行审，代价是“your hours / All human time”），要么“YOLO”（不完全读就合并/发送，代价是“silent errors / All risk”）（第 2 页）——并提出整讲的核心命题：**“生成很便宜，验证很贵”（“Generation is cheap. Verification is expensive.”）**（第 3 页）。
- **验证阶梯（The verification ladder）的五级演进与基准半衰期**（第 3–14 页）：从只靠演示者口说（“The demo era”，如约 1970 年的 SHRDLU，第 4 页）起步，AI 评测走过四级台阶并卡在第五级：
  - Rung 1 人工标注（Human labels，如 MNIST、ImageNet、GLUE）：静态基准有半衰期，达到人类水平的时间从 MNIST（1998）的“~18”年、ImageNet（2009）的“~6”年缩到 GLUE（2018）的“~1”年，而更难的 SuperGLUE 撑了“less than two years”，印证古德哈特定律（Goodhart’s law：“一旦指标成为目标，它就不再是好指标”）（第 5–7 页）。
  - Rung 2 环境奖励（Environment reward）：如 WebShop（2022）含“1M+”商品和“~12K”条人类指令，自动计算所选商品与隐藏目标商品的匹配度，但遗留问题是“奖励只是用户真实意图的代理（proxy）”（第 8–9 页）。
  - Rung 3 开发者测试（Developer tests）：如 SWE-bench（2023）含“2,000+”真实 GitHub issue，在人工核验的 Verified 子集上解决率从 2023 年至今从“2% → 90%+”，但“测试会漏掉东西，所以基准本身也需要被检查”（第 10 页）。
  - Rung 4 模拟用户 + 最终状态检查（Simulated user + final state）：如 τ-bench（2024），用模拟用户跑完后检查最终数据库状态，提出 `pass^k`（同一任务连续 `k` 次全通过），揭示**能力（`pass@1`）和可靠性（`pass^k`）会分离**（第 11 页）。第 13 页指出当前基准的三大通病：饱和太快、测试数据可能泄漏进训练、基准本身有 bug。
  - Rung 5 长任务无现成检查器（`?`）：按 METR 的估算，agent 能以一半成功率完成的任务时长每“4–7 months”翻倍（从 2023 年的 1 分钟走向几天甚至一周）（第 14 页）。“谁来检查 agent 干了一周的活？（Who checks a week of agent work?）”（第 14 页）。
- 为什么长任务的“检查比动手便宜”规律正在消失（第 15 页）：一是错误变得细微且隐蔽（“Errors are subtle and nuanced”），人很难看出来；二是输出量太大（“There is too much output”），超过任何人能审查的容量（第 15 页）。第 16 页由此给出“验证难度 × agent 可靠性”的 2×2 决策表：易验证且可靠 → 委派（Delegate）；易验证但不可靠 → 抽查（Spot-check）；难验证但可靠 → 盲信（Blind faith）；难验证且不可靠 → 不用（Don’t use）。
- **两大支柱之一——可靠性（Reliability，agent 的属性：“每次都能干对吗？”）**（第 16–20 页）：
  - 把评估变成持续闭环（“Deploy → Log every run → Find failures → Write new tests”），结合防背题的活基准（Living benchmarks，如 SWE-bench-Live、LiveCodeBench）、线上生产监控与持续红队测试（Continuous red-teaming）（第 17 页）。
  - 指标不能只看 `pass@1`：第 18 页对比 Agent A 与 Agent B，两者 `pass@1` 都在“~60%”，但 `pass^8` 一个仍约“~60%”，另一个跌到“0%”；同时还要报告种子方差、改写指令和环境变动下的稳定性，以及成本与延迟（第 18 页）。
  - 大规模模拟（每个 agent 跑“1,000s or millions of simulated runs”）来暴露罕见故障并聚类（跳过策略检查、错误工具输入、过早放弃），类比自动驾驶模拟里程和软件模糊测试（fuzzing）（第 19 页）。
  - **给整条轨迹打过程分（Process score），而不只看结果分（Outcome score）**：第 20 页的退单标本里，agent 在第 3 步“跳过身份校验（Skip the ID check）”属于策略违规，第 5 步“退款到一张新卡（Refund to a new card）”属于不安全动作，但最终订单确实被取消了——只看结果分是 Pass，过程分则标出两个隐患，并把“自动检查器最不确定的重要步骤”送给人审（第 20 页）。
- **两大支柱之二——信任（Trust，人与 agent 共同的属性：“人知道什么时候能信它吗？”）**（第 16、21–24 页）：目标是校准过的依赖（calibrated reliance），信得太少和信得太多都是失败（第 16 页）。三个工程手段：
  1. 展示工作证据（Show your work）：不能只交补丁（Output only），要交“产出 + 证据（Output plus evidence）”，包括跑过的测试、引用、日志、形式化证明（如 Lean）和每处修改的理由，让人检查证据而不必重做一遍（第 22 页）。
  2. 指明往哪看（Where to look）：用校准过的置信度、标记不确定片段、改动摘要、按风险等级审查和抽检审计，把审阅者直接带到最需要细看的那几行（第 23 页）。
  3. **挣来的自主权（Earned autonomy）五级阶梯**（第 24 页）：按某类任务的历史战绩逐级放权，对应自动驾驶分级——Level 1 Suggest（人自己干）；Level 2 Draft（人批每一步）；Level 3 Act, ask first on risky steps；Level 4 Act, with sample audits；Level 5 Act alone（且仅限这一类任务）。同时“好 agent 也知道什么时候该开口问（A good agent also knows when to ask）”（第 24 页）。
- 对我们：整讲几乎是为 **单元 12（可靠性与评估）** 和 **单元 21（放手与把关）** 量身定做的核心材料，还串起 **单元 1（自主梯度）** 与 **单元 4（风险审批）**。`pass@1` 同为“~60%”但 `pass^8` 是“~60%”对“0%”（第 18 页）、退单例子里“结果分过关但过程分抓出跳过身份校验与退到新卡”（第 20 页）、验证阶梯与古德哈特定律（第 7、12 页）是 单元 12 一等一的标本；“生成便宜、验证贵”（第 3 页）、“逐行审 vs YOLO”（第 2 页）、2×2 委派矩阵（第 16 页）、“产出+证据”（第 22 页）和“挣来的自主权”5 级阶梯（第 24 页）可直接放进 单元 21 当主体框架。
