# 单元 1｜Agent 全景与 Harness 范式之争

不管你平时用的是 Antigravity、Claude Code、Cursor 还是 Codex，每天都在和 Agent 打交道。这第一个单元不从“大模型是什么”科普，而是把平时大家顺口叫的“Agent”彻底掀开盖子，落到工程架构、底层算术和一线开源源码上。

整个单元解决四个核心问题：怎么用一把不会过时的尺子看透任何 Agent 产品；为什么单步很准的模型在长任务里还是老翻车；2026 年业界争得最凶的“薄 Harness vs 厚 Harness”到底在争什么；以及 **Pi、DeepSeek Harness (`dsh`)、Codex CLI、OpenCode V2、Grok Build** 这五个一线开源 Harness 在代码架构上究竟差在哪里。

学完这个单元，你会走完第一次论文精读（ReAct + *Building Effective Agents*）和第一次大厂面试拷问，最后做一个融合 **Harvard CS2680 Mads-Lens** 与 **Stanford CS146S Week 1** 的真实轨迹解剖实验。这份讲义是课前给你串地图用的，不用提前啃完，课上我们一关一关把源码、观点分歧和面试深水区聊透。

## 关 1.1｜感知-行动闭环与自主梯度：谁来选下一步

网页聊天里你问“测试为什么挂了”，它给你一段分析，最后改代码、重跑测试的还是你；换到 Coding Agent 里，它自己读文件、改代码、跑测试、看到报错再修，直到确认通过才交差。

差别不只在于“会动手”，更在于**看得到动手之后的真实反馈，并据此改变下一步**。早在 1995 年 Russell 和 Norvig 的人工智能经典教材里，就给 Agent 定下了沿用至今的四要素：**环境（Environment）、观察（Observation）、动作（Action）、目标（Goal）**。套到编程 Agent 上，仓库和终端是环境，文件内容与报错是观察，改文件、跑命令甚至“开口问你”都是动作，而测试通过或契约满足才是可验收的目标。

但面对市面上几十种工具，单靠这四个词还不够分清深浅。UMich EECS498 讲师 Marcus Darden 给了一把三年后工具全换名字依然好用的尺子：**“下一步动作，是由谁选出来的？”**

顺着这把尺子看，两件事一下子就透明了：

- **Workflow 和 Agent 的分界**（Stanford CS329Z Diyi Yang）：步骤由程序员用代码写死的是 Workflow，由 LLM 动态挑下一步的是 Agent。两者都是复合 AI 系统，没有谁天生比谁高级。
- **AI 编程工具的自主五级梯度**（UMich EECS498 L05）：从 1 级行内补全、2 级旁侧聊天、3 级结对 CLI（如 Aider：人指定文件和边界，程序按固定 6 步运行，改错时最多自动重试 3 次），一直到 4 级 Agentic CLI（把“选下一步”交还模型，模型自主搜索、读文件、试错修复）和 5 级多 Agent 并行。

反直觉的是，Aider 其实同时具备循环、工具、规划和记忆四个原语，却停在第 3 级——从 3 级跃迁到 4 级并不需要换更聪明的模型，只需要把“挑下一步”的决定权从代码移交给模型。自主级别的提升也不是免费的午餐：越往上走，问你越少，但多轮探索的 token、延迟和出事故的半径都在放大。真正的工程功力是按任务挑对级别，而不是一律上最高级。

关于人在这个时代的角色，几门名校课也从不同角度给出了判断：EECS498 说是从“打字员”转向“策展人”，铁律是“你能解释它，它才是你的”；南大 jyy 讲得更锋利——工程师最后剩下三件事：“信息差、能坐牢（担责）、能驾驭”。课上我们会拿三个真实研发任务练一遍自主级别选型，再过一道关于 Workflow vs Agent 取舍的面试题。

出自 CMU 11-768 L01/L14、Stanford CS329Z L01/L06、UMich EECS498 L01/L05、南大 jyy 第 1 讲。

## 关 1.2｜模型提议、Harness 执行与错误累积的算术

很多初学者下意识觉得“大模型长了手，在帮我敲终端命令”。这一关先钉死一条跨越模型代际的不变原理：**语言模型只会做一件事——根据前面的 token 序列预测后面的 token。它碰不到你的硬盘，也连不上你的网络。**

正如 CMU L01 所说“动作也是 token”，你在工具里看到的每一次执行，底层都是严格的三步接力：

```text
 ┌──────┐  1. 输出动作 token（提议）  ┌─────────┐  2. 校验权限并执行  ┌────────┐
 │ 模型 │ ─────────────────────────▶ │ Harness │ ──────────────────▶ │ 真实环境│
 │无状态│ ◀───────────────────────── │控制循环 │ ◀────────────────── │文件/Shell│
 └──────┘  3. 观察转成文字回传        └─────────┘    输出 / 报错      └────────┘
```

模型发出的是固定格式的请求（具体协议单元 3 拆开），真正查权限、跑命令、抓输出的是包在外面的程序——**Harness**。由此引出全课最硬的一条安全法则（UMich EECS498 L05）：**文字是请求，代码和权限才是强制（Prose asks. Code and permissions enforce.）**。模型只能从一张不是它自己写的工具菜单里点菜，靠 System Prompt 劝阻删除文件永远不是安全边界。

搞清循环之后，就能算清为什么“单步很聪明的模型，长任务还是动不动翻车”：

- **独立复利算术**（Harvard CS2680 L06）：单步准确率 95% 听起来很高，但如果 50 步必须步步不错，0.95 的 50 次方大约只有 7.7%，平均跑 13 次才成 1 次。
- **更致命的自我条件化**（CMU L05 Vending-Bench）：现实里各步并不独立。早期一次错误推断留在上下文里，会持续误导后续几十步，而且强模型更擅长为自己的错误假设自圆其说。
- **破局的关键不在单步盲目刷模型，而在缩短反馈距离**（Stanford CS146S 嘉宾 Eno Reyes）：20 步单步 90% 的任务，最后才查一次成功率只有约 12%；如果每步都有便宜的自动检查器（如类型检查、单测）且失败最多重试 3 次，整体成功率可以直接拉到约 **98%**。

课上我们会算一遍老板让你“换旗舰模型提 3% 单步准确率”的真实投入产出账，并用 CMU L01 的六个经典任务练一遍怎么按动作而非任务名划分“自主 / 审批 / 禁止”边界。

出自 CMU 11-768 L01/L05、Harvard CS2680 L02/L06、UMich EECS498 L05/L06、Stanford CS146S 第 5 周。

## 关 1.3｜范式之争：薄 Harness 还是厚 Harness，训模型还是做系统

把视角再拉高一层：工业级 Agent 从来不是“一个模型”，而是由六根支柱撑起来的系统工程（CMU L01）——**模型、Harness、沙箱、推理服务、可观测监控、训练系统**。后面的 13 个单元，就是把这六根支柱逐一拆开。

想提升 Agent 的六项核心能力（工具准确、长上下文一致、可定制、复杂任务管理、环境理解、安全），永远存在两条互补路线：一条是**训模型**（轨迹 SFT、可验证奖励 RLVR，把能力内化进权重，执行快但黑盒、更新贵）；另一条是**做 Harness 工程**（改工具接口、上下文管理、沙箱权限、编排调度，透明且可热更新，但受限于上下文预算）。

这就引出了 2026 年整个 Agent 工程界最核心的一场观点交锋——**Harness 到底应该越做越薄，还是越做越厚？**

- **薄 Harness 派（Stanford CS146S Mihail Eric、嘉宾 Lee Robinson、Pi 作者 Mario Zechner）**：主张顺应 Bitter Lesson，假设下一代模型会强得多，尽量少在模型外围堆复杂抽象和强约束流程。Lee Robinson 提出“删掉产品（Delete product）”；Claude Code 的系统提示词也从早期的 200 多行一路砍到 50–80 行；Pi 甚至把默认工具压到只剩 4 个。
- **厚 Harness / 系统工程派（Harvard CS2680 Juncheng Yang、南大 jyy、DeepSeek `dsh` 团队）**：拿出硬实测数据——固定同一个模型，仅仅换一套 Harness，SWE-bench Verified 的解决率就能从 43/169 跳到 72/169（Agent = 模型 × Harness）。jyy 第 9 讲更是直指本质：20 行玩具循环悄悄假设了网络不断、没有并发、操作全可逆；一旦进生产，隔离沙箱、幂等恢复、缓存经济、事件日志和权限审计属于**本质复杂性**，模型再聪明 10 倍也替代不了。

把这两派揉在一起，就能拿出一把很清晰的判断尺子（jyy 第 13 讲）：**替弱模型打补丁的启发式规则（Policy）要尽量做薄、随时准备删；连接真实世界的隔离、恢复、验证与观测底座（Mechanism）必须做厚做硬。** 课上我们会拿 6 个具体的 Harness 功能让你亲手分栏，并正面过一道关于“模型升级会不会吞掉你做的 Harness”的面试高频题。

出自 CMU 11-768 L01、Harvard CS2680 L04、Stanford CS146S W1/W3、南大 jyy 第 9/13 讲。

## 关 1.4｜横评五大开源 Harness：从单体到微内核与插件化

光聊理念不够，做 Agent 开发一定要直接看一线开源框架的真实骨骼。

Harvard CS2680 第 8 讲把 Harness 的软件架构划成三级演化：所有模块写死在一个进程里的**单体（Monolithic）**、主控循环通过接口抽象接入可替换组件的**模块化（Modular）**、以及极小核心通过标准协议协调外部独立沙箱/记忆/工具服务的**微内核（Microkernel）**。越往右走，多 Agent 扩展性和故障隔离越强，但通信和排障复杂度也越高。

本机 `materials/harnesses/` 里已经备齐了五个风格截然不同的开源框架源码，我们会在课上直接翻真实目录对照：

| 开源 Harness | 语言与源码规模（本机实测） | 核心架构路线 | 最有代表性的工程选择 |
|---|---|---|---|
| **Pi** (`pi-mono`) | TypeScript，12 packages | 极致极简模块化 | 4 个核心工具 + `<1K` 系统提示、JSONL 分支会话树、零内置审批与 MCP 靠扩展组装、`file-mutation-queue` 串行写文件、带价格门槛的缓存保活 |
| **DeepSeek `dsh`** | TypeScript，61 packages | 一切皆插件（Cordis 微内核） | 连 `agent-loop` 自己都是平级插件；`Session = list[Event]` 单一日志多投影；CAS 乐观锁防并发覆写；独立 `spill` / `guard` / `ptc-runtime` |
| **Codex CLI** (`codex`) | Rust，133 crates/dirs | 工业级二进制 + 多端协议 | Sandbox-first（`bwrap` 无网沙箱先跑，越出边界才问人）；Lark 语法约束 `apply-patch`；`app-server` 协议让 CLI/IDE 共用同一引擎 |

（具体的文件编辑算法、沙箱拦截机制、上下文压缩和中途插话实现，这里先看架构全景，留到单元 3、4、5 逐个深挖。）

课上我们会直接打开其中几个仓库的真实目录树，做一次“给企业后台异步修 Bug 平台做架构选型”的拼装演练，并聊聊 `dsh` 插件化架构潜藏的组合风险。

## 关 1.5｜论文精读：ReAct 与 *Building Effective Agents* + 单元面试拷问

学 Agent 不能只靠二手博客，也不能一个人硬啃 30 页 PDF 犯困。从这一关开始，我们用一套固定的四步节奏带读核心论文，大约每 1–2 个单元精读 1 篇：先锚定当年痛点 → 抓方法骨架与核心图 → 盯死最关键的消融表 → 站在 2026 年的视角挑刺，分清哪些结论已经过时、哪些依然成立。

这一关精读两份奠基材料：

- **ReAct (Yao et al., 2022/ICLR 2023)**：当年纯思维链（CoT）缺外部接地、容易自信幻觉；纯行动（Act-only）缺推理规划、容易原地打转。ReAct 把自由文本的内部推理 `Thought` 与外部动作 `Action`、环境反馈 `Observation` 交织进同一序列，用推理更新自身状态、用观察校正下一步。
- **Anthropic *Building Effective Agents* (2024)**：工业界最常被引用的工程纲领，按控制流区分 Workflow 与 Agent，提出从简起步、按需增复杂度，以及把工具接口当成 ACI（Agent-Computer Interface）来精雕细琢。

站在 2026 年回头审视，两份材料里哪些具体写法已经过时（比如手写 few-shot `Thought:/Action:` 文本格式），哪些反而在今天更显珍贵，以及两份材料和 2026 年重型生产 Harness 之间有什么张力——这些我们留在课上一起拆透。最后会用两道大厂系统设计与架构取舍的模拟面试题给单元 1 收官。

出自 Stanford CS329Z L01/L05/L06、Harvard CS2680 L04。

## 单元实验｜轨迹透视与真实请求解剖

在单元 3 自己造 Harness 之前，我们先融合 **Harvard CS2680 Assignment 1 (`Mads-Lens`)** 与 **Stanford CS146S Week 1 (`Trace Dissection`)** 做一次外科手术级的轨迹解剖：

1. **采集一次真实的复杂会话轨迹**（跨至少 2 个文件 + 至少包含一次失败恢复 + 有多步规划）：可以走 CS146S W1 原版的 `mitmweb` 反向代理抓原始 `POST /v1/messages` 请求体，也可以走 Harvard Mads-Lens 的 `stream-json` 事件流（注意严禁把密钥和原始抓包提交进 Git）。
2. **用现代 Agentic 工作流造一台轻量轨迹透视器**：你先写半页 Spec 定清输入格式和要透视的指标（工具调用、参数、输入/缓存/输出 token、单步耗时、失败重试点、总花费），交给 Agent 实现，你来 Review 代码并拿刚采的轨迹跑通。
3. **写一份落到具体 step 编号的三点工程观测报告**（存在 `work/unit01/trace-lens/report.md`）：记下“用户开口前塞进了多少隐藏上下文”“哪一步走了弯路或浪费了最多 token”“如果你自己造 Harness 最先改哪条设计”。
